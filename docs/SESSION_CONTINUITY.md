# 作業継続システム(5時間制限対策)

Claude の 5 時間使用制限にいつ到達しても作業が失われず、リセット後に**自動で続きから再開できる**ようにするための標準化システム。

## 仕組みの全体像

```
作業中 ──サブタスク完了ごと──▶ チェックポイント
                                ├─ .claude/session-state.md を更新(何をどこまでやったか)
                                ├─ コミット & プッシュ(リトライ付き)
                                └─ [Web] 自動再開トリガーを5時間30分後に張り直し
                                        │
5時間制限に到達(セッション停止)────────┘
                                        │
        ┌───────────────────────────────┴──────────────────────────┐
        │ Web セッション(自動)                  │ ローカル CLI(自動)          │
        │ リセット後に予約トリガーが発火          │ claude-auto-resume.sh が     │
        │ → session-state.md を読んで自動再開    │ 制限を検知 → リセットまで待機 │
        │                                        │ → claude --continue で再開   │
        └───────────────────────────────┬──────────────────────────┘
                                        │
                         タスク完了までこのループを繰り返す
                         (手動の場合は /resume でも再開可能)
```

## 自動再開の2つの方式

### 方式A: Web/リモートセッション — デッドマンスイッチ

時間のかかるタスクの開始時とチェックポイントごとに、Claude が `send_later` で
**5時間30分後**に「自動再開チェック」メッセージを予約する(古い予約は削除して張り直し)。

- 制限で停止した場合 → リセット後に予約が発火し、`session-state.md` を読んで自動で続きから再開
- 無事に完了した場合 → 予約を削除(発火しても「完了済みなら何もしない」ため安全)

この動作は `CLAUDE.md` のプロトコルとして定義されており、全セッションに自動適用される。

### 方式B: ローカル CLI — ウォッチドッグスクリプト

```bash
# 最初のタスクから無人実行
scripts/claude-auto-resume.sh "index.html に問題を50問追加して"

# チェックポイントからの再開だけを任せる
scripts/claude-auto-resume.sh

# 長時間の無人実行(推奨)
nohup scripts/claude-auto-resume.sh "タスク内容" > auto-resume.log 2>&1 &
```

動作: `claude -p` をヘッドレス実行 → 出力から使用制限エラーを検知 → エラーメッセージ内の
リセット時刻(unix epoch)まで待機(検出できなければ30分間隔で再試行)→ `claude --continue -p`
で同じセッションの続きを自動再開 → タスク完了まで繰り返し(デフォルト最大20ラウンド)。

環境変数 `MAX_ROUNDS`(最大再開回数)と `FALLBACK_WAIT`(待機秒数)で調整可能。

## 構成ファイル

| ファイル | 役割 |
|---|---|
| `CLAUDE.md` | 全セッションで自動読込されるプロトコル。こまめなチェックポイントを義務付ける |
| `.claude/session-state.md` | 作業状態の引き継ぎファイル(現在のタスク・完了・次のステップ) |
| `.claude/settings.json` | SessionStart フック。セッション開始時に前回の状態を自動表示 |
| `.claude/skills/checkpoint/` | `/checkpoint` — 手動チェックポイント作成 |
| `.claude/skills/resume/` | `/resume` — チェックポイントから再開 |
| `scripts/claude-auto-resume.sh` | ローカル CLI 用ウォッチドッグ。制限検知→待機→自動再開 |
| `install-global.sh` | 上記をユーザーレベル(`~/.claude`)に展開し、全リポジトリに適用 |

## 使い方

### 日常の作業

特別な操作は不要。CLAUDE.md のプロトコルにより、Claude がサブタスク完了ごとに自動でチェックポイント(状態記録+コミット&プッシュ)を取る。

### 制限が近いとき(手動チェックポイント)

```
/checkpoint
```

現在の状態が保存され、いつ制限に達しても安全な状態になる。`/usage` コマンドで現在の使用率とリセット時刻を確認できる。

### リセット後の再開

新しいセッション(または同じセッションの続き)で:

```
/resume
```

または「続きを再開して」と伝えるだけでよい。セッション開始時にフックが前回の状態を自動表示するため、Claude は文脈ゼロからでも再開できる。

### 全リポジトリへの展開

このマシン上のすべてのリポジトリ・セッションで有効にするには:

```bash
bash install-global.sh
```

- `/checkpoint` `/resume` がユーザースキル(`~/.claude/skills/`)として全プロジェクトで使えるようになる
- プロトコルが `~/.claude/CLAUDE.md` に追記され、全セッションに適用される
- SessionStart フックが `~/.claude/settings.json` にマージされる
- 冪等なので何度実行しても安全。更新時は再実行すれば最新版に置き換わる

## 制限事項(正直な注意点)

- **「使用率95%で自動中断」する公式APIはない。** Claude Code は使用率をフックに公開していないため、閾値での自動停止はできない。代わりに「こまめなチェックポイント+自動再開」で実質的に同じ効果を実現している。使用率の確認は `/usage` で手動で行う。
- デッドマンスイッチ(方式A)は Claude 自身がプロトコルに従って予約を張ることで成立する。制限がチェックポイント間の作業中に到達した場合、直前のチェックポイント以降の作業はやり直しになる(こまめなチェックポイントで損失を最小化)。
- ウォッチドッグ(方式B)の制限エラー検出は CLI の出力文言に依存する。CLI 更新で文言が変わった場合は `is_limit_error` / `extract_reset_epoch` のパターンを更新すること。検出に失敗しても30分間隔のフォールバック再試行で最終的には再開される。
- リモート(Web)セッションのコンテナは一定時間で回収されるため、**プッシュ済みであること**が唯一の永続化保証。ローカル未プッシュの変更はコンテナ回収で失われる。
